# T-021: DSP dependencies: pffft, libebur128 (test-only), EBU test-set fetch, and bundled fonts
- Owner: build-engineer
- Milestone: M1
- Status: DONE
- Depends on: T-002, T-003

## Goal
Integrate the dependencies approved in T-002:
- pffft (marton78 fork, BSD-like), the product FFT library for `SpectrumAnalyser`;
- libebur128 (MIT), as a test-only loudness oracle linked only into the unit test target;
- an opt-in script that fetches the official EBU loudness test set into a gitignored folder, so unit tests can run the true-peak and LRA cases that need the official audio.

## Inputs
- `docs/research/T-002-dsp-references.md`: sections 1 (FFT), 3 (the EBU test set and libebur128) and 10 (the license table).
- `CMakeLists.txt`, `CMakePresets.json` and `docs/dependencies.md` from T-003.
- `docs/roadmap.md`: the Decisions entries dated 2026-09-28 on pffft, libebur128 and the EBU files.

## Scope
1. **pffft.** Pin an exact commit or tag of https://github.com/marton78/pffft, using the same mechanism T-003 chose (FetchContent or submodule). Build only the single-precision real and complex FFT sources as a static library target `investigate_pffft`, with SIMD enabled for x64 (SSE, and AVX if the fork supports it on MSVC). Link it to the plugin shared-code target and the unit test target. Its headers must be includable as `#include <pffft.h>` (or as documented). Suppress third-party warnings for pffft only, so the project stays warning-clean at `/W4`.
2. **libebur128.** Pin a release tag of https://github.com/jiixyj/libebur128. Build it as a static library and link it only to `InvestigateUnitTests`. It must never be linked into the plugin. Add a CMake check that fails the configure step if the plugin target links it.
3. **EBU test set (opt-in).**
   - First read the EBU loudness test set terms of use at https://tech.ebu.ch/publications/ebu_loudness_test_set and summarise them in `docs/dependencies.md`.
   - If the terms allow downloading for internal conformance testing: add a CMake script `cmake/FetchEbuTestSet.cmake`, run with `cmake -P`, that downloads the set into `third_party/_fixtures/ebu/`, verifies a checksum, and unpacks it. The script lives in `cmake/` because `third_party/` is gitignored as a whole; the fixtures folder is already covered by that rule.
   - Add a CMake cache variable `INVESTIGATE_EBU_TEST_SET_DIR`, defaulting to that folder, and pass it to the unit test target as a compile definition, so tests can skip cleanly when the folder is missing.
   - Do not run the download automatically during configure or build.
   - If the terms require the user's explicit acceptance, or forbid scripted download, do not write the script. Set this item to an open question for the user and complete items 1 and 2.
4. **Fonts and license texts (added 2026-09-28).** Fonts are pinned third-party files, so they are handled like pluginval.
   - Add `cmake/DownloadFonts.cmake`. At configure time it downloads, with SHA-256 checksum verification, `Inter-4.1.zip` (https://github.com/rsms/inter/releases/download/v4.1/Inter-4.1.zip) and `JetBrainsMono-2.304.zip` (https://github.com/JetBrains/JetBrainsMono/releases/download/v2.304/JetBrainsMono-2.304.zip) into `third_party/fonts/`.
   - Extract only these files, unmodified:
     - `extras/ttf/Inter-Medium.ttf`, `extras/ttf/Inter-SemiBold.ttf` and Inter's `LICENSE.txt` (store it as `OFL-Inter.txt`);
     - `fonts/ttf/JetBrainsMono-Regular.ttf`, `fonts/ttf/JetBrainsMono-Medium.ttf` and JetBrains Mono's `OFL.txt` (store it as `OFL-JetBrainsMono.txt`).
   - Also copy pffft's license file as `LICENSE-pffft.txt`.
   - Add all of these files to the existing `InvestigateAssets` binary-data target, alongside the SVGs from `assets/ui/`. Use one target, because two targets with the default `BinaryData` namespace would clash. Extend the target's glob or source list to accept `.txt` for these license files.
   - Record the copyright lines of the fonts and of pffft in `docs/dependencies.md`.
   - Sources: `docs/research/T-022-font-licenses.md` and `docs/design/ui-spec.md` sections 3.2, 6.2 and 11.
5. **Documentation.** Update `docs/dependencies.md` with the pinned versions, licenses, usage types (product, test-only or fixture), and update instructions. Also correct the JUCE license row: JUCE 8 is dual-licensed under AGPLv3 or the JUCE 8 EULA (Starter, Indie and Pro tiers), not GPLv3. Cite https://juce.com/legal/juce-8-licence/ as in T-002 section 10.
