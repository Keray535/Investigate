Add every M3c parameter, extend the two choice lists without breaking saved sessions, widen `freqLow` to 1 Hz, and mark the state as version 2. After this task the current editor still builds and works. Nothing reads the new parameters yet; T-052 and the GUI tasks switch the consumers.

## Scope
1. **`channelMode`.** Keep its ID, its 7 choices and their order. The display name becomes "Channel", and the display text of L+R becomes "Stereo". The L/R and M/S texts may gain "(legacy)" only if T-045 asks for it; otherwise leave them.
2. **`underlay`** (new choice): Off, Mid, Side, Left, Right, Stereo. Default Off.
3. **`meterScale`.**
   - Keep its ID and its first four choices (dBFS, K-20, K-14, K-12). The display name becomes "Metering".
   - Append, in this order: dBFS.30, dBFS.15, dBFS+3, K-20 C, K-14 C, K-12 C, LUFS ML, LUFS SL, LU ML, LU SL.
   - Extend `MeterScale.h` to match, with helper functions the processor and the editor need: the K reference, whether the mode is a "C" mode (fixed 600 ms ballistics), and whether it is a loudness mode.
   - The current editor must treat any appended mode safely, as dBFS, until T-057.
4. **New parameters**, per the plan table:
   - `align0dB` (bool, off);
   - `showSidechain2` (bool, on);
   - `meterStyle` (Bars or Density);
   - `meterIntegration` (0.1 to 3000 ms, default 1.00, log skew centred at 30 ms);
   - `meterRelease` (10 to 5000 ms, default 750, centre 500 ms);
   - `meterPeakHold` (0 to 10000 ms, default 1000, centre 1000 ms);
   - `soloWidth` (1/12 to 4 octaves, default 1.0, log skew centred at 0.58 octave, `withAutomatable (false)`).

   Each has text formatting and parsing in the style of the existing parameters. Integration shows two decimals below 10 ms, so the default reads "1.00 ms".
5. **`showSidechain`.** The display name becomes "Sidechain 1 trace"; the ID is unchanged.
6. **`freqLow`.** The range becomes 1 to 1000 Hz, with a log skew centred at 31.6 Hz. The default stays 20 Hz. The formatting handles values below 10 Hz.
7. **`ParameterRefs`** gains raw atomics for every new parameter, for T-052.
8. **State.**
   - `stateVersion` becomes 2.
   - `ensureViewStateDefaults` adds `meterSections` (all visible) and `inputLabel0`, `inputLabel1` and `inputLabel2` ("Main", "SC 1", "SC 2").
   - It adds an empty `ReferenceSlots` child only if T-045 or T-058 needs one at load time; otherwise leave it to T-058.
   - Loading a version-1 state needs no value conversion. Write a test that proves it.

## Acceptance criteria
- [ ] Every parameter in the plan table exists with the stated ID, type, range, default, skew and automatable flag (a table-driven test).
- [ ] **Compatibility.** Three stored version-1 states, generated by the current build before your change and saved as test fixtures, load with identical values for every pre-existing parameter. They cover `channelMode` = L/R dual, M/S dual and Mid; `meterScale` = K-14; and `freqLow` = 20 Hz and 15 Hz. The new parameters take their defaults, and `ViewState` keeps its existing properties.
- [ ] A state round trip (save, then load into a new instance) preserves every parameter, old and new, within 1e-6 normalised. This includes the XML string conversion of `ViewState`.
- [ ] The current editor builds unchanged and works with every choice of every parameter. Selecting an appended metering mode causes no crash or assertion: an on-screen GUI smoke test, gated through `GuiTestEnvironment.h`.
- [ ] pluginval at strictness 10 passes. `processBlock` stays bit-exact (null test) with every new parameter randomised.
- [ ] Warning-clean at `/W4`. `docs/qa/T-051-unit.md` and `docs/qa/T-051-validation.md` report PASS.
