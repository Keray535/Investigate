## 2. Spectrum settings

Confirmed from the full guide text (SPAN User Guide p.3–4 and Primary User Guide p.13–17, "Spectrum Mode Editor"):

- **Slope**: default **4.5 dB/octave**, pivoted around 1 kHz, editable in the "Spectrum Mode Editor" (SPAN User Guide p.3; Primary User Guide p.17). Matches the roadmap's `slope` default of 4.5 dB/oct exactly — **no change**.
- **Block size**: "Fourier block size in samples", user-set via the "Block Size" selector. Higher block size = more low-frequency resolution but less time coherence (temporal smearing) at high frequencies, less frequent spectrum refresh (partly compensated by raising overlap), and more visual latency; needs to scale up with sample rate to keep the same effective resolution (Primary User Guide p.16). **The shipped factory default numeric value is still not stated anywhere in either guide's text** — remains not documented. Recommendation unchanged: keep **4096**.
- **Overlap**: "FFT window overlap percentage" between adjacent FFT blocks, e.g. "80% means the block currently being calculated is overlapped with the previously calculated block by 80% in time"; higher overlap = more frequent updates at higher CPU cost (Primary User Guide p.16). **Default percentage still not stated** — remains not documented. Recommendation unchanged: keep **4x** (Investigate expresses this as a multiplier, not a percentage; 4x ≈ 75%, a reasonable middle value against SPAN's percentage framing, still not a sourced default).
- **Window type(s)**: **confirmed list and default** — "Hann" (default, "best used for music analysis... superior separation between adjacent frequencies, especially at lower frequencies"), "Hi-Res" (non-conventional "Nuttall squared" window for technical/noise-floor analysis), "Blackman" (better separation of quiet components than Hann, worse than Hi-Res), "Dome" (non-conventional, best frequency resolution but least separation of quiet components; also used as the equalizer-window default in some other Voxengo plug-ins) (Primary User Guide p.16). **This changes the roadmap's assumption** that the choice list is Hann/Hamming/Blackman-Harris(4-term)/Flat-top — SPAN's actual four options are a different set with different names and purposes. See §7.
- **Averaging ("Avg Time")**: confirmed definition — "specifies averaging (fall-off) time (in milliseconds) used when the 'RT Avg' or 'RT Max' analysis is active. This value specifies time it takes spectrum level to fall down by 20 dB" (Primary User Guide p.17). So SPAN's Avg Time is not a generic smoothing time constant, it is explicitly defined as *time-to-fall-20-dB*, the same convention SPAN separately uses for its level-meter release time (see §3). **No factory default numeric value is stated.** Recommendation: keep the roadmap's **1000 ms** default, but redefine Investigate's `avgTime` parameter using the same "time to fall 20 dB" convention rather than a generic averaging window, for both terminological and behavioural parity with SPAN and with Investigate's own "20 dB/s" real-time-max release constant (see §7).
- **Smoothing**: confirmed — "Smooth" parameter selects resolution in octaves; purely visual, produces a 6 dB/octave apparent drop for higher-frequency stationary tones versus lower ones (an FFT bin-width artifact, expected and not a bug); this drop does not meaningfully appear on musical (non-stationary) material (Primary User Guide p.17). **Default resolution value not stated.** Recommendation unchanged: keep **1/12 octave**.
- **Secondary curve modes**: **confirmed and refined**, see the corrected 5-mode list in §1. `Max` = infinite peak hold (Investigate's "All-time max"); `Avg` = cumulative average (Investigate's "All-time average"); `RT Max` = real-time max with fall-off, same name as Investigate's "Real-time max"; `RT Avg` is normally used for the *primary* curve, not offered as a secondary-only option in Investigate's roadmap, but that is fine because Investigate's primary curve already applies exponential averaging by design (see `docs/roadmap.md` Architecture). `RT Sigma` (a dynamics/variance overlay) has no Investigate equivalent and is not recommended for v1 — flagged as a possible cheap future addition, not a default change.
- **dB range / frequency range**: SPAN's "Range Low"/"Range High" (power, dB) and "Freq Low"/"Freq High" (Hz) are confirmed as user-adjustable display-range controls (Primary User Guide p.17), but **no default numeric values are given anywhere in either guide**. Recommendation unchanged: keep **−90 dB / +6 dB** and the roadmap's existing frequency defaults.
- **Channel modes / default stereo combination**: SPAN supports multi-channel and Mid/Side analysis via its channel-group/"Underlay" system (SPAN User Guide p.3–4), but **the guide never states which channel-group or combination is shown by default when a stereo instance is first opened**. Remains not documented. Recommendation unchanged: keep **Mid** as Investigate's default (see §7 for the reasoning, unchanged).

## 3. Statistics and meters

Confirmed, all sourced directly from SPAN User Guide p.4–6 unless noted:

- **RMS / "Integr"**: the "RMS"/"Integr" indicator shows "integrated signal power estimation" per channel, reset by the "Reset" button.
- **Max Crest Factor**: shows the maximum reached difference between the RMS/Integr value and a separate, **not directly displayed**, "peak RMS" value. **Peak RMS uses a 50 ms time window** (this upgrades the earlier "inferred/low-confidence" citation to **confirmed**, SPAN User Guide p.4–5). The guide explicitly warns that comparing "Max Crest Factor" across plug-ins is only meaningful if their peak-RMS windows match — a shorter window (e.g. an instant peak) inflates the reported crest factor. This 50 ms window is a dedicated crest-factor helper metric, not SPAN's general-purpose adjustable RMS meter window — confirms the existing gap-table reasoning that Investigate's separate, user-adjustable `rmsWindow` (default 300 ms) is not contradicted by this figure. **No change to `rmsWindow`.**
- **True Peak / Peak, and clipping**: the "True Peak"/"Peak" indicator shows "1-sample output true peak/sample peak level"; it "detects samples that will be clipped if signal is converted to a limited bit depth." A "TP" toggle switches the indicator (and its associated clip counter) between true-peak and sample-peak modes. True-peak clip indication is specifically useful because noise-shaped dither can push levels above 0 dBFS even when sample peaks look safe (SPAN User Guide p.5). This confirms clipping is tied to a 0 dBFS threshold under either metric, with no other numeric threshold documented. No change to Investigate's true-peak/clip design; note that SPAN exposes a user-facing **TP vs. sample-peak toggle** on its clip counters, which Investigate does not currently have (both are computed and shown separately instead) — a reasonable, not-required-for-parity divergence.
- **Correlation meter — CHANGED**: "shows average real-time correlation between two first input channels (**500 ms average**)" (SPAN User Guide p.5–6). This directly sources a number that was previously only an inferred fixed constant. **Recommend changing the roadmap's fixed correlation-integration constant from ~300 ms to 500 ms** (see §7 and §9). Separately, and unchanged from the prior pass, the panel also shows "the average balance (in decibel) between two first input channels during the last 3 seconds," negative meaning the left channel is louder (SPAN User Guide p.6) — Investigate has no equivalent "balance" readout; flagged only as a possible cheap future addition, not required.
- **Metering / K-system / EBU modes — confirmed and expanded** (SPAN User Guide p.5): the "Metering" selector offers: `dBFS`, `dBFS.30`, `dBFS.15` (all unbiased, differing only in meter range), `dBFS+3` (adds a fixed 3 dB bias to the level meter and RMS/Integr readouts only, intended to be paired with the spectrum's "Align 0 dB" + "Slope=0" mode), `K-20`/`K-14`/`K-12` (Bob Katz's K-system, unweighted, no bias, release ballistics *not* forced), `K-20 C`/`K-14 C`/`K-12 C` (calibrated variants: **RMS integration and release time constants are fixed to 600 ms, independent of the plug-in's own Settings**, "as per K-system specification" — no weighting applied), and `LUFS`/`LU` (EBU R128 / ITU-R BS.1770-4 / Tech 3341, with `...ML` = momentary loudness, **0.4 s integration window**, and `...SL` = short-term loudness, **3 s integration window**; both also update an integrated-loudness "Integr" statistic twice a second over a rolling 5-minute window; the "+18" EBU scale and a summary loudness readout are explicitly *not* offered by SPAN). This confirms and sharpens the earlier finding: **only the calibrated "C" K-system variants** fix ballistics to 600 ms — plain K-20/K-14/K-12 do not. Since Investigate's `meterScale` parameter does not include calibrated "C" variants (out of scope), this has **no default-value impact**, only a clarification for any future scope expansion.
- **Crest factor**: not a separate SPAN meter name beyond "Max Crest Factor" above; Investigate's editor-derived peak-minus-RMS crest factor remains a reasonable, uncontradicted design.
- **Reset behaviour — confirmed**: the "Reset" button "can be used to reset counters and start statistical accumulation over" (SPAN User Guide p.5) — a single reset action covering RMS/Integr, Max Crest Factor, and the True Peak Clippings counters shown in the Statistics panel. The guide's UI-elements section for SPAN itself does not separately describe a spectrum-only reset button; the closest documented mechanism is the general Voxengo convention (Primary User Guide p.13, p.18) that **left-clicking the spectrum display itself resets its accumulated Max/Avg-type curve**. This maps well to Investigate's split between `requestStatsReset()` (meters) and `requestSpectrumReset()` (all-time curves, currently triggered by the editor rather than a spectrum click) — recommend `ui-ux-designer` consider adding "click the spectrum to reset its accumulated curve" as an interaction, in addition to (not instead of) an explicit reset control, since it is a documented, low-cost Voxengo convention. Not a required default change.

## 4. Interactions

Now confirmed from the extracted text (SPAN User Guide p.4, and general Voxengo conventions in Primary User Guide p.9–18) — several assumptions in the original pass were **not correct** and are corrected below:

- **Hover/frequency-pointer readout — corrected**: SPAN's only confirmed spectrum-pointer interaction is: "You may right-click on the spectrum to copy the current frequency pointer value to the clipboard (you may then paste it to an equalizer)" (SPAN User Guide p.4). The guide text does **not** describe an on-canvas hover tooltip showing frequency, note name, cents and level together — that is **not documented**, and the earlier pass's phrasing ("known in the community for a mouse-hover readout") should be treated as unconfirmed community description, not a guide-sourced fact. **Recommendation, changed**: `ui-ux-designer` should treat Investigate's richer hover readout (frequency, note name with cents, and level, all visible on hover) as a **deliberate improvement over SPAN's confirmed behaviour**, not a parity claim, and should keep SPAN's right-click "copy frequency to clipboard" idea as an optional inspiration only if useful (e.g. for pasting into a future EQ, though Investigate has none in scope).
- **Freeze ("Hold") — confirmed, matches roadmap closely**: "The 'Hold' switch allows you to hold spectrum updates temporarily for the purpose of visual comparison. Note that spectrum updates will be automatically resumed whenever you switch between channel groups." (SPAN User Guide p.4). This is functionally identical to Investigate's `freeze` toggle. New detail worth adopting: SPAN **auto-unfreezes on channel-mode/group changes** — recommend `ui-ux-designer`/`gui-engineer` consider the same auto-release behaviour when `channelMode` changes while frozen, to avoid a stale, mismatched frozen curve. Not a roadmap default change, a UX-behaviour recommendation.
- **Narrow-band sweep/solo — confirmed, no Investigate equivalent planned**: "You may use the 'narrow-band sweeping/soloing' mode by holding the 'Ctrl' ('Command' on macOS) key. When this mode is not engaged, the plug-in does not affect the sound in any way." (SPAN User Guide p.4). This is an EQ-adjacent feature (band-pass preview/solo of a frequency region) that is out of Investigate's pass-through-only scope and is not recommended for v1; noted for completeness only.
- **Zoom — confirmed as a general Voxengo convention, applicability to SPAN's plain analyser view unconfirmed**: "You may hold the 'Alt' key while dragging the control surface to zoom-in the selected spectrum area. Double-clicking the control surface with the left mouse button while the 'Alt' key is held acts as zoom-out." (Primary User Guide p.14). This is documented under the *Equalizer* chapter (an equalizer's spectrum display shares the same control-surface class as SPAN's), so it likely but not certainly applies unmodified to SPAN's own spectrum view — flagged as **medium confidence**, not fully confirmed for SPAN specifically.
- **Knob/value interactions — confirmed as general Voxengo conventions** (Primary User Guide p.9–10), applicable to SPAN's numeric controls (Block Size, Overlap, Avg Time, Slope, ranges, etc.): drag the knob center for linear up/down adjustment; hold Shift or right-click while dragging for a high-precision mode; scroll the mouse wheel to step the value; **double-click a control to reset it to its default value**; click a numeric readout to type a value directly via the keyboard. This directly supports recommending "double-click to reset to default" and "scroll wheel to nudge" as Investigate's own control conventions, consistent with, not copied verbatim from, SPAN.
- **Underlay / dual-channel display — confirmed**, see §1 and §2; this is SPAN's mechanism for showing two channel-groups' spectra at once and is the closest analogue to Investigate's L/R-dual and M/S-dual channel modes.
- **"Hide Meters and Stats" — confirmed**: a title-bar switch that "hides all meters and statistics panels and extends the spectrum analyzer panel" (SPAN User Guide p.4) — a layout toggle with no Investigate equivalent currently in scope; flagged as a cheap possible addition (collapse the meter panel to give the spectrum more room), not required.
- Comparison with FabFilter Pro-Q's documented Freeze/Freeze Peaks/Spectrum Grab interactions (unchanged from the original pass) still stands as supporting, non-SPAN evidence that "freeze" and "peak hold" are table-stakes; no change to that reasoning.

## 5. Layout

**Now sourced** from the product screenshot embedded on page 1 of the SPAN User Guide (`research/_cache/span/page_1.png`, rendered from `span_guide.pdf`, v3.24). This is an actual current SPAN screenshot, not a generic reference. Described in words, with approximate proportions, no artwork reproduced:

The plug-in window is a single wide panel, roughly 5:2 width-to-height overall, arranged top to bottom in three bands:

1. **Title bar** (thin, full width, top): a light blue-grey strip containing, left to right: a "?" hint toggle, a "Presets" button with a dropdown arrow, an undo/history icon, an A/B state colour swatch, "A"/"B" comparison toggle buttons (the active one highlighted), an "A▸B" state-copy button, a "Routing" button with a dropdown arrow, then a channel-group selector ("LEFT" in the screenshot), "SOLO" and "Copy" buttons, a wide "HIDE METERS AND STATS" button, and at the far right the plug-in's own logo/title ("SPAN") followed by a hamburger-style settings menu icon.
2. **Main body** (the dominant band, roughly 75–80% of the window's height): split horizontally into two unequal columns.
   - **Left/dominant column (roughly 85% of the body's width)**: the spectrum panel. It has its own header row: "Spectrum" label, a "HOLD" button, a colour swatch and "Underlay" label with a channel-group badge (e.g. "RIGHT", shown in an accent colour), and, right-aligned in the same row, a "Mode" label with a "USER" dropdown and a small gear/settings icon. Below that header is the large plot area itself: a dark background with a filled, olive/yellow-green spectrum curve (a slightly darker/more saturated overlaid curve represents the secondary or underlay spectrum), horizontal gridlines, a logarithmic frequency axis along the bottom labelled from 20 to 20k, and a dB scale down the plot's right edge (in the screenshot, roughly −18 at the top to −78 at the bottom) with small up/down spinner arrows for adjusting the visible range. A thin horizontal scrollbar/zoom row with arrow buttons sits directly under the plot.
   - **Right column (roughly 15% of the body's width)**: a narrower "Out" panel — a label at the top, then a tall vertical two-bar level meter (one bar per channel) with a dB scale down its own right edge (in the screenshot, +6 at the top to −60 at the bottom, in 6 dB steps), coloured green in the lower/normal range and yellow/orange near the top, with a thin white horizontal peak-hold marker near the top of each bar; small "L"/"R" labels sit below the meter bars.
3. **Bottom statistics/metering band** (roughly 15–20% of the window's height, full width): divided into three zones left to right.
   - **Left zone ("Statistics")**: a compact two-row grid of per-channel numeric readouts — "RMS" (two values), "Max Crest Factor" (two values), "True Peak Clippings" (two count values) and "True Peak" (two dB values), each row showing left- and right-channel figures side by side.
   - **Centre zone**: a "Reset" button, then a "Metering" label with the current mode shown in a dropdown-style button (e.g. "DBFS") and a small adjacent "TP" toggle badge.
   - **Right zone ("Correlation Meter")**: a "BAL" numeric readout, and a horizontal correlation bar scaled from −1.00 to +1.00 with a filled indicator segment showing the current value.

This is a genuine SPAN layout description (not the earlier pass's generic, unsourced placeholder), still offered to `ui-ux-designer` as **one reference among several**, not a template to reproduce (see §8 on trade dress): Investigate must use its own colours, iconography and panel artwork, but the *functional* zoning (spectrum dominant, a narrow side level-meter column, a bottom numeric-statistics band split into meters/controls/correlation) is a reasonable, sourced starting point for the equivalent Investigate regions.

## 8. IP boundaries

Unchanged from the original pass. Investigate must not reuse, regardless of how close feature parity gets:
- The **name** "SPAN", "Voxengo", or any Voxengo product/company branding, in the product, its marketing, or code identifiers.
- Voxengo's **logos, icons, or any exported/screenshotted artwork**. (T-020 viewed one screenshot for layout research only, per the task's own instructions; nothing from it is reproduced here beyond a worded, proportion-level description.)
- Any **distinctive colour scheme or control-skin graphics** that function as trade dress — i.e., do not attempt to visually clone SPAN's specific look (knob/slider graphics, panel textures, colour palette identity, its specific olive/yellow-green spectrum fill and dark grey chrome), even though the roadmap's "SPAN-inspired dark UI" direction is fine as a *category* of look (dark, technical, meter-and-spectrum layout) as long as the concrete artwork, palette and iconography are original (per roadmap Decisions and Risk #4).
- **Manual/user-guide text.** No sentences, phrasing, or structure from the Voxengo SPAN or Primary user guides may be copied into Investigate's own documentation, tooltips, or in-app hint text. All quotes in this report (now longer and more numerous, since the full text was finally readable) are for internal research attribution only and must not be copied into `docs/design/`, `source/`, or shipped product text.
- **Preset names or preset files.** Not applicable at v1.
- **Any Voxengo trademark** appearing in comparison marketing.
- Feature *behaviour* (parameter names/ranges/ballistics, which meters exist, how they are computed, and now the interaction conventions documented in §4) is not protected by copyright/trademark and is the explicit subject of this report; reproducing behaviour is acceptable and is what T-001/T-020 exist to document. Note in particular that the *window function names* Hann/Hi-Res/Blackman/Dome and the spectrum-type names RT Avg/Max/Avg/RT Max/RT Sigma are generic or industry-standard/descriptive terms (Hann and Blackman are textbook DSP window names; the others are plainly descriptive), not distinctive trademarks — using the same or similar terms in Investigate's own UI is a behavioural-parity choice, not a trademark risk, but Investigate should still write its own tooltip/help copy rather than paraphrase the guide sentence-for-sentence.

- Read all 7 rendered SPAN-guide pages and the full extracted text of both guides. Page 1's screenshot was used for the §5 layout description; no other rendered page contained artwork worth viewing (pages 2–7 are plain text/contents/credits).
- No official product screenshots from voxengo.com were additionally downloaded, because the SPAN User Guide's own page-1 screenshot was sufficient, current (v3.24) and already sourced with a page citation; fetching a second, less clearly versioned image was judged unnecessary.

### Values changed (parity corrections, not just confidence upgrades)
- **Correlation integration**: `~300 ms` (unconfirmed estimate) → **500 ms** (SPAN User Guide p.5–6, "500 ms average"). **Roadmap default recommended to change.**
- **Window choice list**: Hann/Hamming/Blackman-Harris(4-term)/Flat-top (unconfirmed guess) → confirmed SPAN list is **Hann (default)/Hi-Res (Nuttall²)/Blackman/Dome** (Primary User Guide p.16). **Roadmap choice list recommended to change** (default Hann is unaffected).
- **`avgTime` semantics**: generic "averaging time in ms" → confirmed SPAN convention is **"time to fall 20 dB"** (Primary User Guide p.17). **Recommend redefining the parameter's behaviour**, not its default numeric value.
- **Secondary/primary curve model**: corrected from "2 modes, real-time max and all-time max" to the **actual 5-mode `Type`/`2nd Type` system** (`RT Avg`, `Max`, `Avg`, `RT Max`, `RT Sigma`) that governs both the primary and secondary curves (Primary User Guide p.15–16). No roadmap default change; clarifies the underlying model.

### Values confirmed as-is (no roadmap change, confidence upgraded from inferred/unsourced to sourced)
- `slope` default 4.5 dB/oct (now doubly sourced, SPAN User Guide p.3 and Primary User Guide p.13).
- Peak-RMS 50 ms window used only for Max Crest Factor, not the general RMS meter (SPAN User Guide p.4–5) — `rmsWindow` stays 300 ms.
- K-system "C" calibrated modes fix RMS ballistics to 600 ms; plain K-20/K-14/K-12 do not (SPAN User Guide p.5) — no `meterScale` change (no "C" variants in scope).
- Reset button resets RMS/Integr, Max Crest Factor and True Peak Clippings together (SPAN User Guide p.5); spectrum accumulation reset is a documented general Voxengo convention (click the spectrum) rather than a SPAN-specific dedicated button.
- "Hold" (freeze) auto-resumes on channel-group switch (SPAN User Guide p.4).
- "Underlay" is SPAN's mechanism for dual-channel-group spectrum display, matching the intent of Investigate's dual channel modes (SPAN User Guide p.4).
- True Peak/Peak indicator and its TP-toggle are 0 dBFS-referenced clip detectors, with a user-facing switch between true-peak and sample-peak definitions (SPAN User Guide p.5).

### Still not documented in the guide (unchanged from the original pass, now confirmed absent from the *full* text, not just an extraction failure)
- Factory default values for: `fftSize` (Block Size), `overlap` (Overlap %), `avgTime` (Avg Time), `smoothing` (Smooth), `dbLow`/`dbHigh` (Range Low/High), `freqLow`/`freqHigh` (Freq Low/High), and the default `channelMode`/channel-group shown on a fresh stereo instance.
- The real-time-max spectrum curve's own release/fall-off rate as a fixed, non-user-adjustable number (SPAN's `RT Max` fall-off is in fact governed by the same user-adjustable `Avg Time` control, not a separate fixed constant at all — this is itself a correction: Investigate's roadmap treats the real-time-max release as a *fixed* 20 dB/s constant, whereas SPAN's equivalent, `Avg Time`, is *user-adjustable*. This is a legitimate, defensible design divergence — flagged for the architect, not changed unilaterally here).
- An on-canvas hover tooltip showing frequency, note name/cents and level together — not described anywhere in either guide; SPAN's only confirmed pointer interaction is right-click-to-copy-frequency.
- Exact default true-peak oversampling factor and EBU R128 gating parameter values (the guide names the standards followed — ITU-R BS.1770-4, EBU Tech 3341-2016 — but does not restate their numeric internals; Investigate should continue to source those directly from the standards via T-002, as originally recommended).

### New correction for the architect's attention
Investigate's roadmap currently models the real-time-max release as a **fixed** constant (20 dB/s), separate from the user-adjustable `avgTime` parameter. SPAN's own equivalent behaviour (`RT Max` type) is governed by the *same* adjustable `Avg Time` control used for `RT Avg`, with no separate fixed fall-off rate documented anywhere. This is not necessarily wrong for Investigate — a fixed release can be a deliberate simplification — but it is a real design divergence from SPAN, not a value that SPAN simply doesn't confirm. Recommend the architect either (a) keep the fixed-constant design as an intentional, documented divergence, or (b) fold the real-time-max release into the existing `avgTime` parameter for closer behavioural parity. No file was changed to reflect this beyond flagging it here, per this task's read-only-to-roadmap scope.
